# Диаграммы последовательности — Система управления доступом БЦ

Роли: **Арендатор/Сотрудник**, **Охранник**, **Администратор**, **Директор**, **Турникет (СКУД)**, **Система**.

Ниже — ключевые сценарии. Каждая диаграмма в формате **Mermaid** (рендерится на GitHub) и продублирована комментарием с альтернативой.

---

## 1. Выпуск пропуска сотруднику (happy path)

```mermaid
sequenceDiagram
    autonumber
    actor A as Арендатор (менеджер)
    participant S as Система
    actor AD as Администратор БЦ
    actor E as Сотрудник
    actor G as Охранник

    A->>S: Создать заявку на пропуск (ФИО, арендатор, срок, зоны)
    S->>S: Проверить данные и уникальность
    S->>AD: Уведомление о новой заявке
    AD->>S: Выпустить пропуск
    S->>S: Статус = «активен», присвоить номер
    S->>E: Уведомление (email) о готовности пропуска
    S->>G: Синхронизировать список активных пропусков
    E->>G: Предъявить пропуск на входе
    G->>S: Проверить пропуск
    S-->>G: «Действителен»
    G->>E: Пропустить
    S->>S: Аудит: выпуск пропуска
```

## 2. Проход по пропуску (успешный)

```mermaid
sequenceDiagram
    autonumber
    actor E as Сотрудник/Гость
    actor G as Охранник
    participant S as Система
    participant T as Турникет

    E->>T: Приложить пропуск
    T->>S: Запрос проверки (ID пропуска)
    S->>S: Проверить: статус, срок, зоны, чёрный список
    alt Пропуск действителен
        S-->>T: Разрешить
        T-->>E: Открыть турникет
        S->>S: Зафиксировать проход
    else Пропуск недействителен
        S-->>T: Отказать
        T-->>E: Не открывать
        S->>G: Вывести причину отказа
        G->>E: Объяснить ситуацию
    end
```

---

## 3. Проход при недействительном пропуске (отказ)

```mermaid
sequenceDiagram
    autonumber
    actor E as Сотрудник
    actor G as Охранник
    participant S as Система

    E->>G: Предъявить пропуск
    G->>S: Проверить пропуск
    S-->>G: Отказ: «Пропуск заблокирован»
    G->>G: Оценить ситуацию
    alt Пропуск заблокирован ошибочно
        G->>S: Запросить у администратора разблокировку
        Note over G,S: Охранник НЕ может сам активировать (см. Полномочия п.5)
    else Нарушение
        G->>S: Временный бан
        S->>S: Аудит бана
    else Забыл / утерян
        G->>S: Вызвать администратора
        Note over G,S: Охранник НЕ может выпустить временный пропуск (см. Полномочия п.5)
    end
```

## 4. Блокировка (деактивация) пропуска администратором

```mermaid
sequenceDiagram
    autonumber
    actor AD as Администратор
    participant S as Система
    actor O as Владелец пропуска
    actor G as Охранник

    AD->>S: Деактивировать пропуск (ID)
    S->>S: Статус = «заблокирован»
    S->>S: Аудит: кто, когда, причина
    S->>G: Синхронизировать чёрный список
    S->>O: Уведомление о блокировке
    Note over AD,S: Ограничение: администратор НЕ может активировать обратно (см. Полномочия п.3)
```

## 5. Временный бан охранником

```mermaid
sequenceDiagram
    autonumber
    actor G as Охранник
    participant S as Система
    actor V as Нарушитель
    actor AD as Администратор

    G->>S: Забанить временно (ID, срок, причина)
    Note over G,S: Допущение: причина обязательна (иначе произвол)
    S->>S: Статус = «временный бан», таймер
    S->>AD: Уведомление о бане
    S->>V: (опц.) Уведомление о блокировке
    alt Срок истёк
        S->>S: Автоматически снять бан
    else Нужно снять раньше
        AD->>S: Снять бан
        Note over G,S: Охранник НЕ может снять бан сам (см. Полномочия п.11)
    end
```

## 6. Бан директором (кого угодно, бессрочно)

```mermaid
sequenceDiagram
    autonumber
    actor D as Директор
    participant S as Система
    actor V as Любой пользователь
    actor AD as Администратор
    actor G as Охранник

    D->>S: Забанить (любой субъект, бессрочно)
    Note over D,S: Ограничения: нет лимита, нет согласования, нет зон (см. Полномочия п.1,12,14)
    S->>S: Статус = «заблокирован»
    alt Забанен администратор/охранник
        S->>AD: Блокировка доступа к системе
        Note over S,G: Риск: управление системой остаётся без людей (см. Полномочия п.7)
    end
    S->>V: Уведомление (опционально)
    S->>S: Аудит (если ведётся)
```

## 7. Ошибочная блокировка → восстановление доступа

Показывает конфликт полномочий: администратора заблокировали, а разблокировать некому.

```mermaid
sequenceDiagram
    autonumber
    actor D as Директор
    participant S as Система
    actor AD as Администратор
    actor AD2 as Другой администратор
    actor G as Охранник

    D->>S: Забанить администратора (ошибочно/по мотивам)
    S->>AD: Доступ к системе отключён
    AD->>S: Попытка войти — отказ
    Note over AD,S: Администратор не может ни войти, ни разблокировать себя
    AD2->>S: Разблокировать коллегу
    Note over AD2,S: Нет права «активировать пропуск» (см. Полномочия п.3) — тупик
    G->>S: Просит разблокировать
    Note over G,S: Охранник не может снять бан (см. Полномочия п.11)
    D->>S: Снять бан вручную
```

## 8. Действие, которого не должно быть: администратор переписывает владельца

```mermaid
sequenceDiagram
    autonumber
    actor AD as Администратор
    participant S as Система
    actor N as Новый владелец
    actor O as Прежний владелец

    AD->>S: Изменить пропуск
    AD->>S: Заменить ФИО/привязку к арендатору
    S->>S: Пропуск переходит новому человеку
    Note over AD,S: Риск: подмена без создания нового и без аудита (см. Полномочия п.1)
    S->>N: Пропуск действует
    S->>O: Старый доступ утрачен
```

## 9. Обход контроля: проход «хвостом» и по чужому пропуску

```mermaid
sequenceDiagram
    autonumber
    actor E1 as Сотрудник (с пропуском)
    actor E2 as Посторонний (без пропуска)
    participant T as Турникет
    participant S as Система
    actor G as Охранник

    E1->>T: Приложить пропуск
    T->>S: Проверка
    S-->>T: Разрешить
    T-->>E1: Открыть
    E1->>T: Пройти
    E2->>T: Пройти следом («хвост»)
    Note over T,E2: Турникет открылся один раз — прошли двое
    Note over G,S: Система не видит второго; ochrana решает вручную
```

## 10. Отказ системы (офлайн-режим турникета)

```mermaid
sequenceDiagram
    autonumber
    actor E as Сотрудник
    participant T as Турникет (офлайн)
    participant S as Система (недоступна)
    actor G as Охранник

    E->>T: Приложить пропуск
    T->>S: Запрос проверки
    S--xT: Нет ответа (недоступна)
    alt Турникет кэширует список
        T->>T: Проверить по локальному кэшу
        T-->>E: Разрешить/Отказать
    else Кэша нет
        T-->>E: Отказ
        G->>E: Пропустить вручную
        Note over G,S: Нет фиксации прохода, риск (см. Полномочия п.7)
    end
    Note over T,S: После восстановления — синхронизация
```

## Сводка соответствия ролей и полномочий

| Роль | Может | Ограничения (из Полномочия.txt) |
|---|---|---|
| Арендатор/Сотрудник | Проход по пропуску | Нет альтернативы при утере/забыл (п.8,9,10) |
| Охранник | Временный бан, проверка | Не активирует, не оформляет гостя, не снимает бан (п.5,11,12) |
| Администратор | Создать, изменить, деактивировать | Не активирует обратно, нет аудита/удаления (п.3,12,13) |
| Директор | Забанить кого угодно, проход | Нет лимита, согласования, делегирования (п.11–15) |
